# Эпик → роадмап

Эпик: **$ARGUMENTS**

Твоя цель — не начать кодить, а довести эпик до роадмапа, по которому можно спокойно работать.
Правило одно: **сначала найди ответы сам, спрашивай только про то, чего в репозитории нет.**

Прочитай `CLAUDE.md` и `roadmap/README.md` — там конвенция роадмапов и формат задачи. Загляни в
любой существующий `roadmap/*/TASKS.md` как в образец: не ради содержания, а чтобы взять формат, в
котором проект ведёт задачи.

## Фаза 0 · Инвентаризация

**Один** `Explore`, до всех остальных. Его вопрос — «что уже есть, а чего нет»: пройди по источнику
требований (макет, спека, issue) и по коду и верни таблицу «требование → реализовано целиком /
частично, и чего не хватает / нет вовсе», с файлами и строками.

Дождись его и **вложи результат в промпт каждого агента фазы 1 как данность.** Без этого шага
каждый из них восстанавливает картину сам, одну и ту же, своим проходом по тем же файлам — на
проверенном прогоне это утроило расход и не дало ничего сверх первого ответа.

Если эпик про то, чего в коде ещё нет вовсе (новая фича с нуля), фаза 0 короткая: что переиспользуемо
и где похожее уже решено. Пропускать её всё равно не надо — остальным нужна общая опора.

**Инвентаризация — не пересказ твоей постановки.** Требования бери из источника, а не из формулировки
эпика: постановщик может ошибаться в том, что уже сделано, и разведка обязана это поймать.

## Фаза 1 · Разведка

Запусти параллельно, одним сообщением, приложив к каждому промпту итог фазы 0:

- `architect` — границы: какие модули появятся или изменятся, куда лягут данные, состояние,
  навигация; не ломает ли эпик существующие контракты; что обязано идти раньше чего.
- `edge-hunter` — краевые сценарии и вопросы, на которые в репозитории нет ответа.
- `acceptance` — на какие связные срезы бьётся работа, критерии приёмки на каждый, что базовое по
  Кано, что явно вне объёма, какие разрывы видны в самом макете.

Дождись всех троих и сведи находки.

## Фаза 2 · Вопросы

Собери вопросы из отчётов, затем **выбрось те, на которые ответ есть в коде, CLAUDE.md, роадмапах
или макете** — на них ответь сам и покажи ответ.

К оставшимся добавь один свой, который агенты не задают по устройству: **что в этом эпике придётся
сделать такого, чего в источнике требований нет?** Макет рисует экраны, а приложению нужны вещи,
которых художник не рисует: настройки, юридические экраны, состояния обновления, точки входа.
Отдельно спроси себя, нет ли у требования **нетехнического обхода** — купить лицензию вместо того,
чтобы городить экран; взять готовое вместо своего. Такой обход дешевле любой реализации, и его
никто, кроме тебя, не предложит.

Оставшееся — продуктовые и вкусовые развилки: задай через `AskUserQuestion`, **одним заходом**,
максимум четыре штуки, с рекомендацией по каждой.

Если после отсева вопросов не осталось — не выдумывай их, иди дальше.

## Фаза 3 · Роадмап

Напиши `roadmap/<эпик>/TASKS.md` (новый каталог под эпик) в формате, который в проекте уже работает.

### Шапка

- цель эпика, текущий статус, что дальше;
- **«Источники правды»** — таблица «что → где», с путями и номерами строк: где лежат токены, где
  разметка экранов, где логика прототипа, где README дизайн-системы. Исполнителю это экономит час на
  каждой задаче, а тебе оно уже известно из фазы 0 — не выбрасывай;
- **«Что проверено и не меняется»** — отрицательная инвентаризация. То, что совпадает с источником и
  трогать не нужно, названное явно, экономит столько же, сколько список работ;
- **«Принятые решения»** — сквозные развилки, закрытые один раз на весь эпик: выбранный источник
  тона, отклонения от макета с причиной, ответы из фазы 2. Решение, размазанное по «Допущениям»
  отдельных задач, будет переоткрыто в каждой следующей.

### Задачи

`<PREFIX>-NN`, каждая размером **в один PR**: «Источник» → «Объём» → «Зависимости» → «Затрагивает» →
«Приёмка».

Два поля обязательны, потому что по ним `/autopilot` раскладывает работу на волны:
**«Зависимости»** — какие задачи должны быть смержены раньше (или «нет»);
**«Затрагивает»** — модули и ключевые файлы, которые задача правит. Без второго поля автопилот не
сможет отличить две независимые задачи от двух, которые подерутся за одни и те же файлы.

Задача обязана быть проверяемой: «Приёмка» формулируется так, чтобы `acceptance` мог по ней вынести
вердикт, не спрашивая автора.

**Замыкающая задача обязательна.** Последней в эпике идёт проверка того, чего не ловят ни гейт, ни
превью: проход по живому приложению на обеих платформах, прокрутка и жесты, длинные и пустые данные,
и всё, что нужно для выпуска — материалы стора, документация, синхронизация README и CLAUDE.md с
фактическим состоянием. Роадмап без неё заканчивается там, где работа ещё не закончена.

### Конец

Диаграмма зависимостей, предложение волн и раздел «Долг» — найденное, но намеренно не взятое в эпик,
с причиной.

Покажи роадмап в чате кратко — список задач одной строкой каждая — и волны: что пойдёт параллельно,
что последовательно и почему.

## Границы

Код в этой команде не пишется. Ветку не создавай, коммитов не делай. Единственный файл, который
появляется — сам роадмап.
