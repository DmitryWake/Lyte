# Превью и скриншот-тесты в Lyte

Отдельный тест на экран не пишется. Модуль объявляет **один** параметризованный класс, и все его
`@Preview` снимаются автоматически в светлой и тёмной теме. Инфраструктура — `:core:core-screenshot`
плюс convention-плагин `lyte.screenshot`.

Покрыты: `core-design` и все четыре `feature/*/impl`.

## Главное правило

**Скриншоты покрывают только то, у чего есть `@Preview`.** Добавил новый арм `UiState` — заведи на
него превью, иначе состояние выпадает из-под визуального контроля молча, без единой красной сборки.

`@Preview` обязателен:
- на каждый экран и каждый публичный компонент дизайн-системы;
- **на каждый арм `UiState`** — Loading, Error, Empty, Content и любой новый (диалог поверх контента,
  баннер ошибки действия — это тоже отдельные состояния).

Превью снимается с фейковыми данными. Навигацию, живые данные и реакцию на клик скриншот не
проверяет — не путай его с интеракционным тестом.

## Эталоны генерирует только CI

Джоба `screenshots` в `.github/workflows/ci.yml` на запиненном `ubuntu-24.04`. Одна среда рендера —
значит нет расхождений между машинами: на macOS картинки отличаются субпиксельно.

Рабочий цикл: правишь UI → пушишь **только код** → CI перегенерирует эталоны, закоммитит их в ветку
PR и напишет комментарий со списком задетых экранов. GitHub покажет before/after в диффе.

**Руками эталоны не коммитим.** Локально запускать `recordRoborazziAndroidHostTest` можно и полезно —
но только чтобы посмотреть на результат глазами. Перед коммитом обязательно откатить:

```
git checkout -- '*/screenshots/*'
```

и удалить новые PNG, если появились. `*/screenshots/*.png` в диффе от человека — это ошибка.

Побочный эффект: коммит эталонов делает `github-actions[bot]`, и запущенный им прогон GitHub ставит
в `action_required` — владелец репозитория должен нажать «Approve and run». Это не поломка.

## Сверка и диффы

- `verifyRoborazziAndroidHostTest` — локальная сверка. На macOS **ложно краснеет** из-за
  субпиксельных расхождений, это ожидаемо и не поломка.
- `compareRoborazziAndroidHostTest` — дифф-картинки в `build/outputs/roborazzi/`
  (`*_compare.png` — эталон / факт / дифф).
- Сверка **не блокирует** мерж: CI перезаписывает эталоны, поэтому визуальную регрессию ловит
  ревьюер, глядя на изменившуюся картинку в диффе PR.

## Подключение нового модуля

```kotlin
plugins { id("lyte.screenshot") }

kotlin {
    androidLibrary {
        withHostTest { isIncludeAndroidResources = true }  // без ресурсов Robolectric не найдёт шрифты и строки
    }
}
```

Плюс один тест-класс на модуль, где `previewPackage` — пакет **этого** модуля, а не корень
`com.nikolaevskii.lyte`: в classpath лежат и превью зависимостей (например `core-design`), и без
сужения фича сняла бы чужие компоненты в свой каталог эталонов.

## Известная особенность рендера

Русские формы множественного числа падают в `other`: «2 дня назад» в эталоне выглядит как
«2 дней назад». Среда рендера не русская. На устройстве форма правильная — это не баг и чинить в
скриншотах нечего.

Подробности (анимации, темы, порог сравнения) — `core/core-screenshot/README.md`.
