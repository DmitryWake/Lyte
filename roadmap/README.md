# Роадмапы

Планы работ по эпикам. Один каталог на эпик, внутри `TASKS.md` — разбивка на задачи размером в один
pull request.

```
roadmap/
  design-v2/TASKS.md     переход приложения на дизайн v2
  <следующий-эпик>/TASKS.md
```

## Почему отдельный каталог

- `design/` — выгрузка из Claude Design, её файлы правятся только новой выгрузкой (`design/v2.1/`
  и т.д.). Роадмап там инородный: он живёт своей жизнью и меняется каждый день.
- `docs/` — опубликованный сайт (GitHub Pages): privacy policy, лицензии. Внутренние планы туда
  класть нельзя, они станут публичными.

## Формат задачи

| Поле | Что в нём |
|---|---|
| **Источник** | откуда требования: фрагмент макета, issue, обсуждение |
| **Объём** | что именно сделать, пунктами |
| **Зависимости** | какие задачи должны быть смержены раньше, или «нет» |
| **Затрагивает** | модули и ключевые файлы, которые задача правит |
| **Приёмка** | по чему судить, что сделано — так, чтобы проверяющий вынес вердикт без автора |

Последние два поля нужны инструментам: `/autopilot` по «Зависимости» и «Затрагивает» раскладывает
задачи на волны и решает, что можно делать параллельно, а `acceptance` судит по «Приёмке».

Сделанная задача не удаляется — к ней дописывается «Что сделано» и статус. Роадмап заодно работает
журналом решений: почему сделали так, а не иначе, и что осознанно оставили в долг.

Заводит роадмап команда `/epic`, ведёт по нему работу `/autopilot`.
