# core-design

Заглушка дизайн-системы. Сейчас — тонкая обёртка над `MaterialTheme`, ничего больше. Семантические токены (цвета, типографика, spacing, shapes) и компонент-кит подключатся отдельным этапом, по аналогии с `core-design` в референсном проекте Aerly.

## Что внутри

- `LyteTheme(content)` — `@Composable`-обёртка, сейчас эквивалентна `MaterialTheme(content = content)`.

## Использование

```kotlin
@Composable
fun App() {
    LyteTheme {
        // весь UI дерево приложения
    }
}
```

Корень **каждого** экрана оборачивается в `LyteTheme` только один раз — в `App()` (`:shared`). Экраны фич используют голый `MaterialTheme`-API (`Scaffold`, `TopAppBar`, `Text` и т.п.) без явного `style` — совместимость сохранится, когда появятся токены.

## Подключение

```kotlin
implementation(projects.core.coreDesign)
```

Модуль использует только `implementation(...)`-зависимости, ничего транзитивно не экспортирует. Потребитель **обязан** подключить сам:

- `libs.compose.material3` — `MaterialTheme`, `Scaffold`, `TopAppBar` и остальные M3-компоненты.
- `libs.compose.runtime` — `@Composable`.
- `libs.compose.ui` / `libs.compose.foundation` — базовые модификаторы и layout-примитивы.

## Нюансы

- **Не закладывайся на текущий API.** Когда появится дизайн-система, `LyteTheme` начнёт принимать/мапить семантические токены, а `MaterialTheme.colorScheme`/`typography`/`shapes` будут собираться из них — напрямую эти M3-свойства менять нельзя.
- Иконки, шрифты и строки, которые появятся вместе с токенами, будут жить в `composeResources/` этого модуля — сейчас модуль ресурсов не содержит.
- До появления токенов не создавай собственные цвета/отступы «под фичу» — используй голые M3-дефолты, чтобы миграция на дизайн-систему была одноразовой заменой темы, а не точечной правкой каждого экрана.

> При изменении исходников модуля проверь и при необходимости обнови этот README в том же коммите.
